# Security and private information

This candidate is not published and has no configured confidential security-reporting channel or support commitment. Do not put credentials, private context, exploitable details or personal records into a public issue or pull request.

Proposed route, pending owner approval: after the GitHub repository is created, the maintainer enables GitHub private vulnerability reporting (repository Settings, Security, "Private vulnerability reporting") and reporters use the Security tab's "Report a vulnerability" button. This route does not exist until that setting is enabled, and no response-time commitment is made. Until then, keep potential reports local and seek an approved confidential route without disclosing sensitive details. This document does not invent an inbox or claim someone is monitoring reports.

For local incidents, stop affected work, preserve redacted evidence, revoke or rotate exposed credentials as appropriate, and reconcile uncertain external actions under owner authority. Deleting the latest file does not remove a secret from Git history. Never silently rewrite another repository's history.

The source-local reader, policy instructions and receipt checker do not sandbox a model or authenticate an operator. Use actual runtime permission controls. All sensitive provider destinations and consequential actions require explicit approval.
